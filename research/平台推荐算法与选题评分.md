# 平台推荐算法与选题评分研究

> 生成日期：2026-08-12 ｜ 用途：为 `scripts/suggest_topics.py` 的「选题推荐综合评分」提供算法依据
> 方法：优先官方文档/官方技术团队披露，第三方结论一律标注「行业推测」

## 结论先行

| 平台 | 推荐核心 | 对选题最要紧的三件事 |
|---|---|---|
| 抖音 | 多目标推荐系统：召回→粗排→精排→混排/探索；2024 起提高「播放时长」「长期主动互动」「搜索联动」权重 | ① 选题有搜索价值（用户会搜）② 表达能留人（完播/停留）③ 深度行为（收藏/关注/评论）比浅赞更有用 |
| 小红书 | 去中心化社区分发，官方未公开权重公式；行业共识为「内容质量分决定初始流量池，互动/收藏/评论/搜索反馈决定加推」 | ① 封面点击率是第一道闸 ② 选题自带收藏/评论价值 ③ 标题埋搜索关键词 |
| 微信公众号 | 三轨流量：关注分发 + 看一看（社交+算法）+ 搜一搜；官方口径更看重原创、清晰标题、真实互动、专业价值 | ① 标题清晰完整、主题明确 ② 选题要有转发欲（观点/共鸣）③ 长尾关键词有持久搜索流量 |

## 一、抖音

### 1.1 推荐链路（官方参与标准 + 官方升级解读）

- 标准链路：候选集「过滤消重 → 召回 → 粗排 → 精排 → 多样性/探索」。中国信通院、北京抖音等联合发布的《TTAF 227-2024 推荐算法干预控制实施指南》明确列出「过滤消重、预估排序」等环节；行业解读普遍描述为「百万候选池 → 几千召回 → 粗排 → 精排」。
- 两大模型（官方升级解读，见参考 [2]）：
  - **价值模型**：对内容全局打分，指标相对稳定——点击率、完播率、播放时长、留存、点赞等，决定内容「质量分」；
  - **预测模型**：结合用户信息（ID/性别/地域/历史行为）、作者信息、内容信息做个性化概率预估，所以同一视频对粉丝/非粉丝分数不同。
- **2024 年官方升级重点**（参考 [2]，运营研究社转述抖音官方升级）：
  1. 提高「播放时长」和「用户长期主动互动」（关注、评论、收藏等深度行为）权重，不再只看 3 秒完播和浅层点赞；
  2. 打通内容流量池与交易流量池；
  3. 「搜索+推荐联动」：约 22% 的抖音流量与用户搜索相关，76% 创作者因搜索获得更多流量，近一年 80% 用户每月使用搜索。
- 官方作者方法论「VALUE」：内容力=停留(Volume)+互动(Activate)+涨粉(Linked)，交易力=选品(Upgrade)+经营(Engaged)。

### 1.2 流量池 / 冷启动（行业推测，官方未公开完整阈值）

- 行业普遍描述：初始流量池 → 同赛道赛马 → 数据达标逐级加推 → 爆款全域池；「前 30 分钟完播率 <45%、点赞率 <3%、转发率 <0.8% 停止追加推荐」等阈值来自第三方援引巨量算数基准（参考 [1]），**非官方公开承诺**。
- 官方可确认的部分：创作者中心有流量分析（哪些关键词带来流量、看后搜什么），说明系统在主动利用搜索意图。

### 1.3 对选题的启示

1. 选题要有「搜索价值」：用户会搜的词/问题/对比（教程、排行、价格、教程、怎么选）。
2. 表达第一优先级是「留人」：钩子、节奏、信息密度决定停留时长。
3. 「收藏/关注/评论」等深度行为权重大于点赞：选题要有干货可藏、有观点可评。
4. 垂直度影响赛马对手：持续同垂类选题更容易跑赢同类内容。

## 二、小红书

### 2.1 官方公开口径（诚实说明：官方没有公开完整算法公式）

- 小红书官方未发布过 CES 公式或推荐权重的权威文档；公开可见的是**蒲公英信用等级**体系（商业合作平台）：「信用等级优秀，会被优先推荐」（参考 [5]，官方宣传口径）。
- 小红书技术团队在公开技术分享中披露的是**推荐系统架构**（召回/排序/实时计算、多目标），未披露内容权重公式（参考 [3][4]）。
- 官方加热工具「薯条」帮助口径：用点击率、完读率判断内容潜力；第三方转述的「点击率 ≥11% 为优质、互动率 ≥3% 为优质」**无法溯源到官方文档**，只能算行业参考（参考 [6]）。

### 2.2 行业共识（第三方推测，注意区分）

- 流传最广的「CES 评分」：`点赞×1 + 收藏×1 + 评论×4 + 转发×4 + 关注×8`（多个来源表述一致，参考 [7][8]，但均非官方文档，权重可能随时间调整）。
- 分发逻辑行业共识：笔记发布 → 初始曝光 → 封面点击率决定「曝光→阅读」转化 → 互动/收藏/评论/搜索反馈决定是否进入更大流量池 → 搜推互通（搜索流量占比高）。
- 账号垂直度、违规记录、商业笔记占比（官方曾建议商业笔记不超过当月 20%）会影响账号整体权重。

### 2.3 对选题的启示

1. 封面/标题点击率是第一道闸：选题再热，封面标题不抓人也白搭。
2. 选题要自带「收藏价值 + 评论话题」：清单、教程、避坑、观点争议。
3. 标题埋搜索关键词：用户搜什么、笔记标题就对齐什么。
4. 垂直度优先：同垂类持续输出，账号标签才清晰。

## 三、微信公众号

### 3.1 官方披露

- **看一看推荐（腾讯技术工程官方文章，参考 [9]）**：
  - 链路：召回（兴趣画像/协同/公众号/社交）→ 粗排（万级）→ 精排（千级 CTR 预估）→ 异构内容混排（强化学习多目标）；
  - 多目标：点击、阅读时长、分享、点赞、评论、关注公众号，避免纯 CTR 造成标题党；
  - 内容属性：分类/tag/实体词/topic/曝光/点击/质量分，以及基于社交影响力的「权威分/精英分」（people rank）。
- **公众号推荐机制官方口径（微信公开课 2026-07，参考 [10]）**：
  - 推荐流量波动是正常现象，不一定是被限流；
  - 更看重：标题清晰完整、内容主题明确的原创内容；真人创作和真实分享、与用户友好互动；对用户有价值（启发/共鸣）；专业领域认证作者的真实经验。
- **搜一搜（微信官方社区客服，参考 [11]）**：
  - 不保证每篇都收录；排序受「运营时间、运营频率、历史违规行为、用户使用行为反馈、关键词匹配程度」共同决定。

### 3.2 对选题的启示

1. 标题要「清晰完整、主题明确」：少用故弄玄虚，多用明确主题词。
2. 社交推荐权重大：选题要有转发欲——鲜明观点、身份认同、可分享的干货。
3. 搜一搜 = 长尾流量：围绕搜索关键词（教程/对比/报告/解读）做选题有持久价值。
4. 专业垂类 + 认证/深度内容更容易获得推荐倾斜。

## 四、综合评分模型设计（映射到 suggest_topics.py）

### 4.1 评分因子与依据

| 因子 | 平台依据 | 数据来源（现有/可采集） | 建议权重 |
|---|---|---|---|
| IP 相关度/垂直度 | 三平台都吃垂类识别 | 现有 `IP_KEYWORDS` | ×3 |
| 时效性 | 抖音冷启动窗口、小红书初始曝光期、公众号新闻性 | 现有 `published_at`（需补推楼 1 号 `hour_key` 解析） | ×2 |
| 话题关注度 | 抖音搜索/热度、小红书搜推互通、公众号热点 | heat（推楼 score/今日热榜数值）、rank、跨源次数 | ×2 |
| 表达势能（钩子/冲突/数字） | 抖音完播/停留、小红书封面点击率 | 现有 `IMPACT_RE`/`CONTRAST_RE` | ×1 |
| 搜索价值 | 抖音 22% 搜索流量、小红书搜推、公众号搜一搜 | 新增「教程/怎么/对比/排行/价格/教程」关键词库 | ×1 |
| 持久/收藏价值 | 抖音收藏权重提升、小红书收藏权重、公众号收藏 | 新增「清单/步骤/公式/避坑/模板/源码」关键词库 | ×1 |
| 观点独特性/共鸣 | 抖音「有共鸣/有惊喜表达」、公众号转发欲、小红书评论话题 | 新增「观点词/身份词/争议词」库 + 反常识/悬念公式命中 | ×1 |
| 跨源热度加成 | 多源印证=话题关注度高 | 现有去重逻辑 | 每多一源 +4 |
| 合规风险 | 三平台都有社区治理 | 现有 `COMPLIANCE_BLOCK` | 一票否决 |

### 4.2 公式草案

```
总分 = IP相关度×3
     + 时效分×2        (≤12h +3, ≤24h +2, ≤48h +1, >72h −2, 未知 0)
     + 关注度×2        (heat 按该源最大值归一化到 0-5；无 heat 用 (10−rank) 分档)
     + 表达势能×1      (0-5：数字/冲突/悬念/情绪词命中数)
     + 搜索价值×1      (0-5：命中搜索型关键词)
     + 持久价值×1      (0-5：命中干货型关键词)
     + 独特性×1        (0-5：反常识/悬念/身份/观点词)
     + 跨源 ×4/源      (同标题每多一个源 +4)
```

合规命中直接剔除；建议在选题推荐文件中输出「分数构成拆解」，让每条候选能看到自己靠哪个维度胜出。

### 4.3 落地增量（都已有数据基础）

1. `fetch_hot_topics.py`：推楼 1 号保留 `score` 到雷达文本（已带 `（9）` 形式，需解析）；今日热榜保留 `.e` 热度。
2. `suggest_topics.py`：新增关键词库（搜索型/干货型/观点型）+ 细粒度时效档位 + 分数构成输出。
3. 选题页：候选卡片展示各维度得分条，可一键「沉淀为经验」回写数据飞轮。

### 4.4 已落地（2026-08-12）

- `scripts/suggest_topics.py` 已按上表实现综合评分：`时效×2 + 热度×2 + 表达×1 + 搜索×1 + 持久×1 + 独特×1 + 跨源×4/源`，合规一票否决；时效档位 ≤12h/≤24h/≤48h/≤72h/>72h 对应 +3/+2/+1/0/−2，热度按同源最大值归一化到 0-5，无热度值用 rank 折算。
- **IP 垂直度改为准入门槛**（2026-08-13）：`ip < 1` 直接不推荐，不进入展示总分；总分为表格可见各维度之和，避免出现“隐藏分”造成合计对不上。
- 新增「热度解析」：推楼 `（9）`、谷歌趋势 `（500+）`、今日热榜 `（100.2万热度）` 等行尾标注自动提取，不误判 4 位年份。
- JSON 与选题推荐 md 均输出 `score_breakdown` 分数构成拆解；工作台候选卡片展示构成行（悬停可见公式）。
- 推楼 1 号纳入 `OVERSEAS_SOURCES`，选题推荐会正确标注「海外源·需人工复核」。
- 单测：`tests/test_suggest_topics.py` 覆盖热度提取、时效档位（含推楼 hour_key）、文本五维、热度归一化与跨源加权。
