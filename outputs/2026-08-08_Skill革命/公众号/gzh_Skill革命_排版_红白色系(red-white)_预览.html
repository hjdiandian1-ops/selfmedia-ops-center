16 分钟做完 96 个实验：AI 的下一个风口，是把老师傅的经验打包成 Skill

复旦实验室 16 分钟跑完 96 个样本、GitHub 仓库一夜涨 2258 星、Meta Skill 把 5 个原子技能拼成「超级白皮书」——经验正在变成 AI 时代的新资产。

昨天，我的热点雷达抓到两个几乎同时发生的信号。

一个是 GitHub 日榜：一个叫 reverse-skill 的仓库，单日涨了 2258 颗星，冲上 2026 年 8 月 4 日的日榜第一，总星标 17,677。另一个是更早一周的新闻：量子位报道 OpenSquilla 发布 Meta Skill——Skill 的 Skill。

工具圈的朋友看到的是「又有新仓库火了」，我看到的是另一件事：行业正在把「经验」本身变成一种商品。

真正让这个判断落地的，是一组工业级账本：复旦大学科研团队把「脂质体介导转染」「siRNA 设计优化」这类高度专业的科研操作封装成可调用模块，机械臂 16 分钟完成 96 个样本的高通量实验。过去，一个学生要学几个月才能上手；现在，老师傅的经验被压缩进了一个 Skill，机器直接调用。

模型还在卷参数，用户还在追新工具。但拉开下一轮差距的，可能是另一种能力：把老师傅的经验打包成 AI 能复用的 Skill。

一、先算账：把几个月带教压缩成 16 分钟

先把账算清楚。

复旦这套系统，投入的「本体」不是算力，是经验——转染条件的坑、样本处理顺序、失败重试的规则。这些经验过去在带教老师傅脑子里，几个月才能传一个人；封装成 Skill 之后，机械臂 16 分钟跑完 96 个样本，而且每一次执行都是标准化的。

再看编排层。OpenSquilla 的 meta-kid-project-planner：400 多行 SKILL.md，5 个原子 Skill 拼接，全程无需人介入，自己跑了 20 多分钟，交付了一份完整的 7 天项目规划包，约 3000 字，还额外做了一轮安全审查。它的智能模型路由，让同类任务 Token 成本比主流 Agent 省 60-80%。

这两组数字说明同一件事：经验一旦变成文件，就从「老师的稀缺资源」变成了「组织的可复制资产」。

二、渗透率：不是概念，是巨头和社区一起投票

Skill 不是小众玩法，它的标准化只用了三个月。

2025 年 10 月 16 日，Claude 发布 Claude Skills；12 月 18 日，Anthropic 把 Skills 发布为开放标准。同一个月，ChatGPT 出现了几乎一模一样的架构——相同的 SKILL.md 文件、相同的目录组织；微软、腾讯等旗下工具也官宣支持。到 2026 年 1 月 21 日，Anthropic 官方 Skills 库星数已接近 5 万。

社区侧的热度更直接：reverse-skill 5 月 13 日开源，8 月 4 日冲到 GitHub 日榜第一；OpenSquilla 的 9 个 Meta Skill 发布时仓库已有 2000+ 星。

Anthropic 核心工程师 Barry Zhang 在一场行业论坛上说得很直白：「别造 Agent 了，造 Skills 就行。」

三、机制解剖：为什么 Skill 能「无痛」装进 AI

Skill 不是把提示词写长一点，它的关键机制是「渐进式加载」。

AI 启动时只扫每个 Skill 的元数据——名称和描述，大约 100 tokens；真正需要时才加载完整的 SKILL.md，大约 3000 tokens。这意味着一个 Agent 可以装备 100 个技能，平时几乎不占上下文，干活时才打开说明书。

很多人会把 Skill 和 MCP 搞混。一句话区分：Skill 是菜谱，MCP 是厨具。Skill 是静态、可移植的说明书，回答「这件事怎么做」；MCP 是实时协议，回答「你能连到什么工具和数据」。Sentry 联合创始人 David Cramer 的原话是 "If skills teach you to cook, MCP provides the instruments that let you do it"——两者互补，不是替代。

Meta Skill 则更进一层：它把「项目经理的操作手册」也写成了文件——哪些步骤并行、哪些串行、哪个产出喂给下一步，全编排好。当一个 Skill 内嵌多个 Skill，拼接起来就是一本「超级白皮书」，端到端打通长程工作流。

四、稀缺品论证：工具会泛滥，私有 Skill 是资产

模型可以一夜降价，工具可以免费开放，但「沉淀下来的经验文件」没法一夜生成。

新京报采访的开发者说得很准：未来企业的竞争力，有可能直接取决于私有 Skills 的沉淀数量与质量，取决于能否把隐性知识高效转化为标准化的可执行模块。普通人已经在做这件事——「花叔的自动化写作」技能，4800 人安装，迭代 2 个月 20 版以上，产出 10 篇以上万阅读文章。

当然，风险同样存在：GitHub 上个人开发的 Skill 可能隐藏恶意代码，私有化封装才是安全边界。这也是为什么「自己写的 Skill」比「全网下载的 Skill」更值钱——它天然带着你的判断、你的流程、你的数据。

▲ 技能沉淀飞轮：经验 → 文件 → 复用 → 修正 → 版本库（小吴聊制图）

顺带说一个我的实证：我这个「小吴聊」内容工厂，本质上就是把主编经验写进 SKILL.md、再靠状态机编排的一条流水线——热点雷达、三平台成稿、双轨质检、草稿箱同步，每天三个档位无人值守，人工只出现在选题和发布两个卡点。工具都是公开的，真正属于我的，是那几百行规则和每次返工沉淀的修正记录。

五、行动判断：三件事，本周就能做

第一，别先追新工具，先写一份 SKILL.md。把你最常做的、流程最固定的那件事——周报、选题、报销、客户跟进——用自然语言写成「名称 + 描述 + 步骤 + 检查清单」，放进 Codex/ChatGPT/Claude 能读取的目录，让它按这个流程干活。

第二，先单点后编排。一个 Skill 只干一件事：搜集信息、写初稿、二审核验，拆成 3 个原子 Skill，再考虑用 Meta Skill 或状态机把它们串起来。不要一上来就编排 20 步的巨型流程。

第三，把返工记录变成版本历史。每次 AI 做错，就把「错在哪、怎么改」追加进对应 SKILL.md 的检查清单；每迭代 5 次存一个版本。你的私有技能库会像复利一样越滚越厚——这也是「花叔」那个 4800 人安装的技能能持续迭代的原因。

写在最后

把今天的账收一下：

工业侧：复旦团队把数月带教的经验封装成 Skill，机械臂 16 分钟完成 96 个样本；生态侧：Claude 3 个月完成从发布到开放标准，ChatGPT、微软、腾讯跟进，reverse-skill 单日 +2258 星；资产侧：工具会泛滥，私有 Skills 的沉淀数量与质量正在成为新的竞争力。

模型解决「懂不懂」，Skill 解决「会不会」。

当老师傅的经验可以被文件化、被调用、被迭代，AI 的下一个风口也许不是更聪明的模型，而是更会打包经验的人。问题留给你：你手里最值钱的经验是什么？如果只能先写一个 SKILL.md，你写哪个？
