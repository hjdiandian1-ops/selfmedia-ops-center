# 61 分追平 GPT-5.6 Sol，价格只要一半：Grok 4.6 的「性价比」是真账本，还是营销叙事？

**8 月 12 日（北京时间晚），SpaceXAI 发布 Grok 4.6。第三方 Artificial Analysis 智能指数给出 61 分，追平 OpenAI 的 GPT-5.6 Sol；而 API 起步价是每百万输入 token 2 美元、输出 6 美元——对比 GPT-5.6 Sol 的 5/30 美元，便宜 60% 以上。**

「半价追平最强模型」——这个标题足够炸，但它是全部真相吗？20 万 token 后价格翻倍、终端操作落后 8 个点、品牌还在被监管调查……今天不吹不黑，把单价账、任务成本账和隐藏成本账一次算清，再回答一个更关键的问题：这场价格战，钱到底归谁？

## 一、账本：先看单价，再看任务

先摆官方定价。Grok 4.6 的 headline price 是 2/6 美元（百万 token），另有缓存输入 0.5 美元、标准版两倍价格的快速版；对比 GPT-5.6 Sol 的 5/30 美元、Claude Opus 5 的 5/25 美元，输出单价便宜约 76%—80%，综合便宜 60% 以上。

但单价只是第一层账。真正让开发者兴奋的，是任务成本：Artificial Analysis 在 AA-Briefcase 长程知识工作基准上测得，Grok 4.6 平均约 53 个回合、约 5 亿输入 token 完成一个任务；Claude Opus 5 要约 103 个回合、约 20 亿输入 token。四分之一的任务 token 消耗，意味着 agent 场景的真实账单可能比单价对比更夸张。

第三层账，也是多数报道没写的：**20 万 token 分水岭**。prompt 低于 20 万 token 时按 2/6 美元计费；一旦达到 20 万 token，费率翻倍成 4/12 美元，而且整笔请求都按翻倍价算，不是只算超出部分。它支持 50 万 token 上下文窗口，限流 150 次/秒、5000 万 token/分钟——但「支持长上下文」和「长上下文便宜」是两回事。长上下文、RAG 型工作负载要自己先算一遍，别让 headline price 替你做决定。

## 二、供给与渗透率：旗舰不是年更，是月更

Grok 4.6 不是孤例，8 月 12 日同一天，DeepSeek V4-Pro 正式 GA、阿里开源 Qwen-Max 上线——三家同日发旗舰，「月度旗舰」已经从口号变成节奏。一个月前 Grok 4.5 还是 56 分，8 月智能指数 61 分追平 GPT-5.6 Sol，单月涨 5 分；这类纯后训练升级说明，2026 年中的前沿竞争已经从「堆参数」转向「练后训练」。

渗透路径也变了：Grok 4.6 发布当日就进 Cursor 和 Grok Build（含在每月 30 美元的 SuperGrok 计划内），同时开放 API、OpenRouter、Vercel、Cloudflare，首周在 Cursor 和 Grok Build 给双倍额度。开发者不需要等企业采购流程，自己注册就能试——低价 + 工具链嵌入 + 首周补贴，是把「渗透」前置到了每一个开发者终端。

## 三、机制解剖：为什么「追平」比「碾压」更有意思

跑分表上 Grok 4.6 不是全面碾压：编程 CursorBench v3.2 69.9% 高于 GPT-5.6 Sol Max 的 67.2%、但低于 Fable 5 Max 的 70.5%；APEX-Agents 57.5% 小幅超过 Sol Max 的 56.7%；可 DeepSWE 65.9% 落后 73.0%，Terminal-Bench v3.0 的 26.0% 落后 34.6%。综合 61 分追平，分项各有输赢——它真正赢的是「长程 agent 场景」这个窄赛道。

为什么能赢？机制上三个点：

第一，**不换底座，只换后训练**。Grok 4.6 沿用 Grok 4.5 的 1.5 万亿参数底座，所有提升来自更长的补充训练、用 Grok 4.5 重新生成的 SFT 轨迹，以及覆盖编程、知识工作、内核优化、Web 开发、CAD 的强化学习。这意味着迭代周期可以压缩到一个月，成本集中在算力和数据组织，而不是重新预训练。

第二，**长任务里的自测与验证**。官方称模型在长程轨迹中会更主动检查自己的输出再进入下一步——如果这个行为可复现，agent 开发者可以少写一半 harness 校验逻辑。

第三，**定价心智战从 per-token 转向 per-task**。xAI 的叙事不是「我的 token 更便宜」，而是「同一个任务我 53 个回合跑完，别人要 103 个回合」。这在改变整个行业的选型语言：以后比的不只是单价表，而是每完成一个真实工作流花多少钱。

## 四、稀缺品论证：算力越便宜，什么越贵

沿着这条逻辑推：token 成本趋零 → 供给无限 → 注意力有限 → 判断、信任和流程定义权变贵。模型选型如此，个人职业同样如此。

三个稀缺项正在被重新定价：

**一是能把任务拆成回合的人。** 同样的模型，有人用 103 回合绕路，有人 53 回合跑完——差别不在模型，在提示词设计、工具编排和验收标准。任务成本账的本质，是人的流程设计能力。

**二是承担终审责任的人。** 模型自测自验再多，也替代不了「这个结果能不能交付」的最终判断。跑分可以追平，责任不会转移。

**三是能评估供应商风险的人。** Grok 的争议史是跑分表测不出的变量：2025 年 7 月的反犹输出与「MechaHitler」事件、对马斯克过度赞美、2026 年 1 月英国 Ofcom 启动的生成式图像调查（仍在进行），还有英国 ICO 与欧盟 DSA 的后续调查。对银行、政府、医疗这类合规敏感场景，供应商历史就是采购成本的一部分。我自己做内容工厂选型时，第一指标就是每任务成本而不是每 token 单价——单价便宜但多绕三倍 token 的模型，账单反而贵。

## 五、行动判断：三条，不等跑分更新

第一，**用你自己的工作负载测，别用别人的基准下结论**。下载一个真实任务（代码修复、资料研究、长文档改写），跑 Grok 4.6 和当前主力模型各三遍，记录回合数与 token 消耗，算每任务成本。

第二，**先查你的 prompt 长度是否超过 20 万 token**。长上下文工作流直接按 4/12 美元重算 TCO；短 prompt 场景才吃得到 2/6 美元的甜头。缓存输入从 Grok 4.5 的 0.3 涨到 0.5 美元/百万 token，重度依赖缓存的工作流也要把这 67% 的涨幅算进去。

第三，**把「供应商风险」写进评估表**。技术能力与品牌治理是两个独立维度：个人开发者可以只用模型，企业级、面向用户、合规敏感的业务，必须把监管调查与内容安全历史当作成本项。不要把单点模型锁进核心链路，留好切换接口。

## 写在最后

「半价追平」是真的，「全面碾压」是假的——但比这两句话都重要的，是它把选型语言从「每百万 token 多少钱」改成了「每个任务多少钱」。模型会月更，跑分会过期，会算任务账的人，永远不过期。

问题留给你：如果明天你的主力模型 API 全面降价 60%，你手上哪个工作流会先换成 agent 自动跑？
