## 二、📕 小红书成果规格

### 2.1 文案.md(硬指标,逐条核对)

- [ ] 首行 frontmatter 契约:`job_id` / `platform: 小红书` / `consumed_materials`(核心素材 100% 在内)/ `hook_formula`(公式编号)
- [ ] 标题:≥3 个候选,每个标注 `dbs-xhs-title` 公式编号,覆盖 ≥3 类心理触发器(数字冲击/身份代入/冲突对比/悬念好奇/反常识)
- [ ] 正文:痛点驱动 + 强 Hook 开头(前 2 行抓住人)+ 具体数字 ≥2 处 + 引导互动(评论/收藏)
- [ ] 末尾标签:**5-8 个搜索标签**(机器 C9 校验,<5 直接 FAIL),含 1-2 个蹭热点词
- [ ] 互动引导:必须含评论区/收藏/点赞/关注等 CTA(机器 C9 校验,缺失直接 FAIL)
- [ ] 参考来源:紧凑版「数据来源:xx/xx」一行(有官方数据时)

### 2.2 视觉卡片(3:4)

- [ ] `rednote_<主题>_slides.html`:Swiss/杂志风结构化卡片,数据可视化为主(不靠 AI 生图)
- [ ] 每页截图 `xhs-01.png~04.png`:**1080×1440**(3:4),本地 playwright 渲染,无需生图 API
- [ ] 封面套路:首屏大标题 + 核心数字/冲突点,3 秒可懂(对齐「标题 3 秒原则」)
- [ ] 无孤行/无堆砌:单页信息密度适中(每页 1 个论点 + 1-2 个数字)
- [ ] **关键数字对比必须可视化**:素材包有可对比数字时,≥1 张卡片使用条形/占比组件(`h-bar-chart`/`bar-tower`/`data-viz`,C12 机器校验)

## 三、📰 公众号成果规格

### 3.1 文案.md(硬指标)

- [ ] frontmatter 契约:`job_id` / `platform: 公众号` / `consumed_materials` / `hook_formula`
- [ ] 具体数字 ≥2 处(单价/百分比/对比,须有官方来源)
- [ ] 真实项目/工具名 ≥1(如 NAS/n8n/ComfyUI/真实型号)
- [ ] 第一人称经历/观察 ≥1 段(源自种子素材或 `source_type: 真实数据/用户投喂`;无种子素材向用户索取,严禁脑补)
- [ ] 禁用 AI 腔开头(「在过去…/随着…/市场上出现了…」)+ 营销号套话(对照 style-guide 黑白词表)
- [ ] 深度文章:多级小标题 + 金句引用 + 文末「参考来源」区块(列名称+关键数字+**可点击链接**)
- [ ] **无整段重复**(机器 C9 校验);参考来源禁止「链接待补/来源待补」
- [ ] **参考来源格式(论文式)**:小号灰字(条目 12px `#9CA3AF`、编号 `[1][2]…`),禁止红色背景药丸/红色文字,分隔线浅灰
- [ ] **数据可视化 ≥2 个组件**(机器 C11 校验):表格/水平条形/占比条/KPI 对比卡,由 `scripts/generate_data_viz.py` 生成
- [ ] 复杂对比图(环形占比等)用 PNG 图卡 + `[[IMG:路径]]` 占位符,推送前必须替换为微信图 URL(C11 校验)

### 3.2 排版 HTML

- [ ] `gzh_<主题>_排版_<主题色>.html`:应用 `gzh-design-skill` 主题(如红白/摩玉绿),深色模式可选
- [ ] `gzh_<主题>_排版_<主题色>_预览.html`:由 `scripts/generate_gzh_preview.py` 生成(带「一键复制到公众号」按钮,必交付)
- [ ] `mobile_check.png`:同一脚本生成 390px 移动端截图,首屏无孤行、无断行(应用 `xiaowan-wechat-layout-skill` 检查)
- [ ] HTML 可直接粘贴进公众号编辑器(样式内联,无外链依赖)

## 四、🎬 短视频成果规格(选配)

- [ ] `120s黄金分镜脚本.md`:五段式(0-3s Hook / 3-15s 切入 / 15-60s 硬核拆解 / 60-90s 避坑反转 / 90-120s 升华金句)

## 五、质检与落盘标准(产出完成后必须自检)

### 5.1 机器自检(必跑,命令固定)

```bash
python3 scripts/validate_materials_contract.py outputs/YYYY-MM-DD_主题名/ --out outputs/YYYY-MM-DD_主题名/validate_report.json
python3 scripts/harsh_critic_score.py      outputs/YYYY-MM-DD_主题名/ --out outputs/YYYY-MM-DD_主题名/harsh_report.json
python3 scripts/generate_score_report.py   outputs/YYYY-MM-DD_主题名/
python3 scripts/generate_gzh_preview.py --input outputs/YYYY-MM-DD_主题名/公众号/gzh_<主题>_排版_<主题色>.html --screenshot outputs/YYYY-MM-DD_主题名/公众号/mobile_check.png
```

- [ ] `validate_report.json` verdict = `PASSED`(FAIL 0)
- [ ] `harsh_report.json` score ≥ 85 且 verdict = `PASSED`
- [ ] 核心素材引用率 = 100%(素材衰减 = 不合格)
- [ ] 素材包 `真实数据` 全部带可打开链接(C8);小红书 ≥5 标签+CTA、公众号无重复段/链接待补(C9)
- [ ] `评分报告.md` 已落盘(机器初筛版由 generate_score_report.py 生成,必须人工复核六维后定稿)
- [ ] 公众号 HTML 含 ≥2 个 `data-viz` 组件、无 `[[IMG:` 残留(C11);小红书 slides 含条形/占比可视化(C12)

### 5.2 人工/Agent 复核

- [ ] 标题 3 秒可懂;正文无 AI 腔、无营销号套话、无虚构案例
- [ ] 卡片/排版视觉达标(无孤行、无堆砌、首屏震撼)
- [ ] `outputs/` 三级目录整洁,无 `process_*`/散落临时文件

### 5.3 状态机推进

- [ ] Job 状态逐环节推进至 `archive`(发布前);`publish_log.json` 在发布动作后落盘
- [ ] 任一环节失败:**从断点恢复**(`job_state.py show`),不重跑全流程
- [ ] `run_daily_pipeline.py --qa` 通过后自动推进 `review → archive`,缺 state.json 或前置产物直接 REJECTED

### 5.4 Git 提交规范(P1 起生效)

- [ ] 项目已纳入 Git 管理(基线 `b11c08c`);每个 Job 归档后提交一次,message 形如 `feat(job): 2026-08-07_主题名`
- [ ] 禁止提交:`.env`、`nas-n8n/shared_files/*.json`(Cookie)、图片/视频产物(已由 .gitignore 拦截)
