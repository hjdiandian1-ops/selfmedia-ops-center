## 二、📕 小红书成果规格

### 2.1 文案.md(硬指标,逐条核对)

- [ ] 首行 frontmatter 契约:`job_id` / `platform: 小红书` / `consumed_materials`(核心素材 100% 在内)/ `hook_formula`(公式编号)
- [ ] 标题:直接选定 1 个(≤20 字,含空格/标点/表情),交付文案不出现多选;所用 `dbs-xhs-title` 公式编号写入 frontmatter 的 `hook_formula`
- [ ] 正文:≤1000 字(含末尾标签与表情),纯文本可直贴——禁止 Markdown 符号(`**`/`###`/`-` 等),重点用换行、数字、emoji 突出
- [ ] 正文内容:痛点驱动 + 强 Hook 开头(前 2 行抓住人)+ 具体数字 ≥2 处 + 引导互动(评论/收藏)
- [ ] 末尾标签:**5-8 个搜索标签**(机器 C9 校验,<5 直接 FAIL),含 1-2 个蹭热点词
- [ ] 互动引导:必须含评论区/收藏/点赞/关注等 CTA(机器 C9 校验,缺失直接 FAIL)
- [ ] 参考来源:紧凑版「数据来源:xx/xx」一行(有官方数据时)

### 2.2 视觉卡片(3:4)

- [ ] `rednote_<主题>_slides.html`:Swiss/杂志风结构化卡片,数据可视化为主(不靠 AI 生图)
- [ ] 每页截图 `xhs-01.png~04.png`:**1080×1440**(3:4),本地 playwright 渲染,无需生图 API
- [ ] 封面套路:首屏大标题 + 核心数字/冲突点,3 秒可懂(对齐「标题 3 秒原则」)
- [ ] 无孤行/无堆砌:单页信息密度适中(每页 1 个论点 + 1-2 个数字)
- [ ] **底部留白统一(机器硬门 · 2026-08-08 数据飞轮沉淀)**:卡片内容区底部距页脚锚点 ≤120px(1080×1440 画布),禁止大面积空档;推荐 `.poster` 用 flex 纵向布局 + `.body{flex:1; justify-content:space-between; padding-bottom:96px}` 让任意内容量都撑满画布;`scripts/render_deck_to_images.py` 渲染时逐卡测量,超阈值输出告警并以退出码 1 拒绝交付
- [ ] **关键数字对比必须可视化**:素材包有可对比数字时,≥1 张卡片使用条形/占比组件(`h-bar-chart`/`bar-tower`/`data-viz`,C12 机器校验)

- [ ] frontmatter 契约:`job_id` / `platform: 公众号` / `consumed_materials` / `hook_formula`

- [ ] 深度文章:多级小标题 + 金句引用 + 文末「参考来源」区块(列名称+关键数字+**可点击链接**)
- [ ] **无整段重复**(机器 C9 校验);参考来源禁止「链接待补/来源待补」
- [ ] **参考来源格式(论文式)**:小号灰字(条目统一 11px、编号 `[1][2]…`,名称 `#6B7280`/说明 `#9CA3AF`),禁止红色背景药丸/红色文字,分隔线浅灰
- [ ] **数据可视化 ≥2 个组件**(机器 C11 校验):表格/水平条形/占比条/KPI 对比卡,由 `scripts/generate_data_viz.py` 生成
- [ ] 复杂对比图(环形占比等)用 PNG 图卡 + `[[IMG:路径]]` 占位符,推送前必须替换为微信图 URL(C11 校验)

### 3.1.1 深度长文结构模板（硬核拆解型 · 2026-08-07 样本沉淀）

适用:**行业现象 / 成本坍塌 / 门槛消失 / 热点爆款解剖**类选题。七段式结构,缺一段即视为浅文:

1. **Hook(现象 + 反常识缺口)**:用反差数字开局(如 30 元 vs 500 万播放),并抛出全文要回答的问题(为什么偏偏是它?钱归谁?),禁止只复述新闻。
2. **一、账本**:拆成本/价格结构,落到具体数字与来源。
3. **二、供给/渗透率**:证明不是个例,给出行业规模或占比。
4. **三、机制解剖(为什么是它)**:解释传播/爆款机制(景观 vs 故事、看完率/分享率、生产与分发分离、审美/文化稀缺),把个案升级为机制。
5. **四、稀缺品论证**:从经济学推演稀缺品(成本趋零 → 供给无限 → 注意力有限 → 流量与信任变贵),再落到 3 个可操作稀缺项;第一人称/工作流只作一句话案例。
6. **五、行动判断**:给读者 3 条可执行判断,不复述数据。
7. **升华收尾**:一句判断力金句 + 一个留给读者的问题。

硬性反模式(命中即退回重写):
- **禁止独立「我的系统 / 自我实证」章节**;个人经历只能作为方法论的一句话案例(如 NAS 内容工厂只在「工作流」论证里出现一句)。
- 结尾禁止仅复述前文数字(必须提供信息增量)。
- 行业类选题必须回答「为什么火」和「价值/钱归谁」,只列数据 = 浅文。

### 3.2 排版 HTML

- [ ] `gzh_<主题>_排版_<主题色>.html`:应用 `gzh-design-skill` 主题(如红白/摩玉绿),深色模式可选
- [ ] `gzh_<主题>_排版_<主题色>_预览.html`:由 `scripts/generate_gzh_preview.py` 生成(带「一键复制到公众号」按钮,必交付)
- [ ] `mobile_check.png`:同一脚本生成 390px 移动端截图,首屏无孤行、无断行(应用 `xiaowan-wechat-layout-skill` 检查)
- [ ] HTML 可直接粘贴进公众号编辑器(样式内联,无外链依赖)
- [ ] **正文插图统一宽画幅(2026-08-08 数据飞轮沉淀)**:正文图片宽高比 ≥1.6:1(16:9 或更宽),禁止竖向长图;竖版 Pexels 素材用 `sips -c <高> <宽>` 中心裁切(原图保留在 `_source/`);流程/结构图用宽版 HTML 画布(如 1500px 宽)直接渲染,禁止交付长条截图
- [ ] **数据组件微信推送图卡化(2026-08-08 终版)**:微信对自定义 HTML 组件还原不可靠(已实测),本地 HTML 组件仅用于预览与 C11 质检;`gzh_draft_api.py` 推送时自动把每个 `data-viz` 组件渲染成 680px 宽 2x PNG 图卡并上传为微信 URL,保证 100% 还原;制图 PNG 一律元素截图渲染(禁止 full_page 视口截图),规格见 [数据可视化规范.md](file:///Users/xiaowuliao/Projects/自媒体发布agent/workflows/数据可视化规范.md) 三·五/三·六
