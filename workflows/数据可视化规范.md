# 数据可视化规范（公众号 + 小红书）

> 目标：让“数据图表”成为双平台产出的标准强制能力，而不是偶发加分项。
> 机器校验：`validate_materials_contract.py` C11（公众号）/ C12（小红书），不达标直接打回。
> 只对**后续新文章**生效，历史文章不返工。

---

## 一、硬指标（机器可校验）

| 平台 | 要求 | 检查码 |
|---|---|---|
| 公众号 | 排版 HTML 必须包含 **≥2 个** `data-viz` 组件（table/bar/ratio/kpi）；正文图片不得残留 `[[IMG:...]]` 占位符 | C11 |
| 小红书 | slides HTML 必须包含条形/占比可视化标记（`h-bar-chart` / `bar-tower` / `data-viz`）≥1 | C12 |

## 二、组件清单与使用场景

统一用 `scripts/generate_data_viz.py` 生成（内联样式，可直接粘贴公众号编辑器）：

| 类型 | 适用场景 | 示例 |
|---|---|---|
| `table` | 多行对比、企业清单、参数对照 | 企业清单表、模型参数对比 |
| `bar` | 两组以上数值对比 | 缓存命中 0.02 元 vs 未命中 1 元 |
| `ratio` | 单指标占比 | 95% 产量 vs 4% 播放量 |
| `kpi` | 核心数字并列、涨跌对比 | 50 倍价差 + 90% 命中率 |
| `complex`（PNG） | 环形占比、多层结构等复杂图 | 三层产业结构占比 |

## 三、使用规则

1. **数据来源**：图表中的数字只能来自素材包 `source_type: 真实数据 / 用户投喂` 条目；`AI推断` 数字禁止入图。
2. **来源标注**：每个组件必须带“数据来源：xxx”脚注（组件自动渲染）。
3. **配色**：默认红白系主色 `#DC2626`；同一篇文章内组件主色必须一致。
4. **样式约束（微信安全版 · 2026-08-08 实测沉淀）**：组件以**单层 `<table>`** 为准（前几日文章实测可准确还原；微信编辑器不支持在 `inline-block` 百分比宽度元素上直接加 padding，`box-sizing` 会失效导致列换行）。硬规则：**禁止嵌套 table**（bar 的行内条用 `<tr><td colspan=2>` 放 div 实现）；单元格文字要短、**禁止 → 等易错符号**；表头与数据列宽一致（34%/33%/30% 等）；不用 flex/grid/SVG/class。
5. **密度**：公众号每篇 ≥2 个组件；同一段话里不要堆 3 个以上组件，图表之间保留文字过渡。

## 三·五、制图 PNG 规格（2026-08-08 数据飞轮沉淀）

1. **宽画幅**：正文插图宽高比 **1.6:1 ~ 2.4:1**（16:9 到 2.2:1 为佳），禁止竖长图与过扁横幅（>2.5:1 手机端字太小）。
2. **设计宽度 1200px**（DPR 2 导出 2400px 宽）：文字可读、微信端 680px 展示时字号约 11-14px。
3. **元素截图渲染**：用 Playwright 对 `.wrap`/内容节点截图（`locator.screenshot`），**禁止 `page.screenshot(full_page=True)`**——视口高度会被算进图里，产生大块底部空白（本期飞轮图曾因此带 54% 空白）。
4. **内容紧凑**：无大块纯白带；块间间距用固定 margin，不要用 flex `space-between` 撑满固定高度画布。
5. 复杂图（环形占比等）仍走 `generate_data_viz.py --png`；结构图/流程图用宽版 HTML 源文件（存 `公众号/_source/`）按上述规格渲染。

## 三·六、微信推送一律图卡化（2026-08-08 终版策略）

**结论：微信编辑器对自定义 HTML 组件的还原不可靠（table/div 均实测错乱），停止依赖 HTML 存活。**

1. 本地/预览仍保留 HTML `data-viz` 组件（供质检 C11 与预览）；**推送时 `gzh_draft_api.py` 自动把每个组件渲染成 680px 宽 2x PNG 图卡**，经 `media/uploadimg` 上传后以 `<img>` 插入正文——图片是像素级还原，100% 等于设计稿。
2. 该行为由 `replace_viz_with_images()` + `generate_data_viz.render_html_block_to_png()` 实现，已内置单测（`tests/test_gzh_draft_viz.py`），无需人工干预。
3. 若人工复制粘贴排版 HTML 进公众号编辑器（非 API 推送），同样建议先把组件换成图卡再粘贴；图卡文件可临时用 `render_html_block_to_png()` 生成。

## 四、生成命令

```bash
# HTML 组件（输出片段，可粘进 gzh 正文）
python3 scripts/generate_data_viz.py --spec tmp/bar.json --out /tmp/bar.html

# 复杂图 PNG（750px，双倍清晰度）
python3 scripts/generate_data_viz.py --spec tmp/donut.json --png --out outputs/<job>/公众号/chart_donut.png
```

spec JSON 示例（bar）：
```json
{
  "type": "bar",
  "title": "缓存命中价差",
  "primary": "#DC2626",
  "items": [
    {"label": "缓存命中", "value": 0.02, "display": "0.02 元/百万 Token"},
    {"label": "缓存未命中", "value": 1, "display": "1 元/百万 Token"}
  ],
  "source": "DeepSeek 开放平台公告（2026-08-06）"
}
```

## 五、公众号复杂图（PNG）插入流程

1. 用 `--png` 生成图卡，保存到 `outputs/<job>/公众号/`；
2. 在 gzh HTML 正文中写入占位符：`[[IMG:outputs/<job>/公众号/chart_donut.png]]`；
3. 推送草稿时，`scripts/gzh_draft_api.py` 会自动调用微信 `media/uploadimg` 把图片上传为 URL 并替换占位符；
4. 推送前若还有 `[[IMG:` 残留，C11 直接 FAIL。

## 六、小红书卡片

- 直接使用 guizang 卡片模板内置的 `h-bar-chart` / `bar-tower` 组件（Swiss 数据类版式）；
- 素材包中只要有可对比数字（≥2 个可比项），至少 1 张卡片必须用条形/占比可视化，禁止纯文字罗列。
